# G2 排空与定向交接

同一个锁定版本的调度副本支持 B0、B1、B2。B0 沿用原版准入规则和队列顺序。B1 按等待时间和活跃 LoRA 上限触发排空，暂停被选适配器的新请求准入，已有请求继续生成。B2 使用相同触发和排空规则，释放后给触发排空的请求一次优先检查机会。当前实现限定单卡、单实例、FCFS 和本地 KV。

第一版固定等待阈值为 500 ms、预留期限 10 秒、目标适配器冷却 1 秒。候选按首次进入调度队列的单调时间排序，同时间按请求 ID 排序。排空对象是在途请求数最少的活跃适配器，同计数按适配器 ID 排序。同一时刻最多维护一个预留。

B2 保留目标原来的队列位置，优先检查时复用原版 token、并发和 KV 检查。调度器实际接纳请求后才移除该队列项并记录交接成功。如果优先检查失败，清除预留并允许同一轮检查其他候选。取消、过期、目标变得不可用和上游抢占会关闭相关预留。B1 以其他适配器先填满最后一个种类名额作为一次错失机会。

复跑命令在 WSL 项目目录执行。

```bash
bash scripts/run_g2.sh results/g2/replay-001
```

实验使用 A/B 七对请求，间隔 45 ms，C 和 D 分别在 235 ms 和 290 ms 到达。A/B 最多生成 96 token，C/D 最多生成 32 token，三种模式均固定 `max_loras=2`。逐模式保存源码副本、真实流式绑定检查、服务端事件、客户端记录和摘要。定向交接验证使用这一条固定短轨迹，正式评估需要独立负载与配对种子。

| 复跑 | 模式 | C 排队 ms | D 排队 ms |
|---|---|---:|---:|
| 1 | B0 | 7430.9 | 7382.9 |
| 1 | B1 | 6880.5 | 6882.0 |
| 1 | B2 | 3266.1 | 6868.5 |
| 2 | B0 | 6534.7 | 6467.4 |
| 2 | B1 | 6331.7 | 6330.5 |
| 2 | B2 | 2946.5 | 6288.4 |

两次复跑中，B1 为 C 触发排空后，较早入队的 A 先占用了释放的最后一个名额。B2 记录了 C 的 `slot_released → handoff_attempt → admit → target_admitted` 链条。C 的排队时间相对 B1 分别缩短约 52.5% 和 53.5%，D 在两种策略下的排队时间接近。该轨迹每组只有一个 C 和一个 D，可解释准入机制，正式 P95 与 Goodput 待 G3 测量。

两次共 96 条竞争回放请求均完成。逐请求检查确认无重复准入和抢占，活跃 LoRA 种类数未越界。54 条流式绑定检查均通过，三种模式的独立参考输出一致。13 项自动测试通过，包含取消、过期、冷却、多个候选、多空位，以及 token、KV、并发失败后的预留回收。资源失败和取消用确定性测试覆盖，真实服务轨迹验证的是名额竞争与成功交接。

首轮用于验证初版机制，第二轮使用补充了多空位计数边界检查的最终版本。证据分别保存在 `results/g2/competition-01/` 和 `results/g2/competition-02/`。
