# 补充配对实验：排空后出现名额竞争

原 G3 使用较平稳的到达轨迹，12 个 B1 运行均未记录名额错失。本实验单独检验突发热门流量会不会制造可交接机会。沿用同一调度器、RTX 5070、四种 LoRA、500 ms 触发阈值和正式 G3 的延迟目标。B1、B2 共用每条轨迹。该结果单独报告。

配置在运行前写入 `configs/g3-competition.json`。种子为 2063、3191、4787，每条种子轨迹有三波。每波在 216 ms 内计划发送七对 A/B，随后约 236 ms 发 C、327 ms 发 D。最多同时运行八条，因此预期已有较早到达的 A/B 留在队列中。种子决定小幅发包抖动、提示词和每波热门输出上限。固定测量窗口 36 秒内，TTFT ≤ 2 秒且 TPOT ≤ 120 ms 的完成请求计入 Goodput。

按种子检查 B1 是否出现 `slot_taken`，并将其中的冷门目标按轨迹序号与 B2 对齐。B2 必须先记录 `handoff_attempt`，再有同一预留的 `target_admitted`，才计为该目标的成功交接。逐目标配对可解释机制，冷门 P95 和整体 Goodput 用来检验代价。预定门槛仍为冷门 P95 降幅至少 20%，整体 Goodput 降幅不超过 5%。

在 WSL 项目目录使用独立 vLLM 环境执行。

```bash
~/work/vllm-lora-admission/.venv/bin/python -m bench.run_g3 \
  results/g3/competition-replay --config configs/g3-competition.json
python3 -m bench.analyze_g3 results/g3/competition-replay
python3 -m bench.analyze_competition results/g3/competition-replay
```

## 实测结果

三组种子共六轮，每轮 48 条请求。288 条全部完成，无超时、未准入或抢占。B1 在 3/3 个种子配对中错失名额，每波恰好一次。9 次错失均由 C 触发，名额均被较早入队的 A 占用。相同轨迹序号的 9 条 C 在 B2 全部实际获得交接，排队分别缩短约 2.95–3.99 秒。

| 种子 | C 排队 P95，B1 → B2 | D 排队 P95，B1 → B2 | 合并冷门排队 P95，B1 → B2 | 合并 P95 降幅 | 达标请求，B1 → B2 |
|---:|---:|---:|---:|---:|---:|
| 2063 | 7.67 → 3.76 s | 7.71 → 7.53 s | 7.84 → 7.39 s | 5.7% | 24 → 24 |
| 3191 | 7.62 → 3.83 s | 7.59 → 7.65 s | 7.69 → 7.53 s | 2.1% | 24 → 24 |
| 4787 | 7.46 → 3.48 s | 7.44 → 6.97 s | 7.47 → 6.96 s | 6.8% | 24 → 24 |

以 seed 2063 第一波为例，B1 中 A 第 8 号比 C 第 14 号早入队。C 触发 A 排空后，A 第 8 号先占满最后一个种类名额，C 等到 6.33 秒才准入。B2 中释放的名额实际交给 C，C 等待缩短到 3.11 秒。之后，因队列里还有早到的 A，第 8 号 A 成为后续排空的目标。D 第 15 号的排队时间仍约 6.19 秒，接近 B1 的 6.26 秒。

B2 合并排队 P95 的配对中位降幅为 5.7%，三组均低于预定的 20%。Goodput 每轮均为 24/36，即约 0.667 条/秒。达标请求全是 A/B，C/D 无一达到 2 秒 TTFT 门槛。热门排队 P95 在三对中均增加约 0.98–1.40 秒，固定 SLO 下的 Goodput 持平仍有热门尾部代价。该负载每轮有六条冷门请求，合并 P95 的慢端转为主要由 D 决定。

当前证据支持 B2 可保护发生竞争的单个目标。该策略在这组突发负载下没有达到冷门合并 P95 的目标，当前保留 B0 默认。原始结果和两种图表在 `results/g3/competition-independent-01/`，逐目标证据在 `competition-requests.csv`，按种子比较见 `pairs.csv`。

[镜像到达顺序诊断](g3-cold-order.md)进一步核对了原实验的九波。B2 的排空目标均为 C → A → D。交换 C/D 后，三波均转为 D → A → C，成功交接也转移到较早到达的 D。
