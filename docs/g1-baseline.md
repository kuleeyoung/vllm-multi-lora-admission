# G1 原版准入阻塞复现

2026-11-18，RTX 5070，vLLM 0.33.0，Qwen3-0.6B BF16，同一套 A/B/C/D rank 8 适配器。调度器来自 G0 锁定源码，观测副本保留原准入判断及队列顺序。服务启动日志和 `scheduler_loaded` 事件可核对实际调度进程。每组预热后重放相同轨迹，改变的服务参数为 `max_loras`。

轨迹共 16 条请求，每隔 100 ms 发送一对 A/B，共七对。C、D 分别在 150 ms 和 350 ms 到达。A/B 生成上限 96 token，C/D 为 32 token，回放忽略 EOS。三轮 `max_loras=2` 和一轮 `max_loras=4` 的轨迹 SHA256 均为 `7211f81c580665622c95d0d22d0ccbf6c0db01bc281b44cbe6f31e2c3ea49a6e`。

| LoRA 上限 | 轮次 | C 排队 ms | C 跳过次数 | D 排队 ms | D 跳过次数 |
|---:|---:|---:|---:|---:|---:|
| 2 | 1 | 6780.5 | 103 | 6603.7 | 98 |
| 2 | 2 | 6782.6 | 103 | 6600.8 | 98 |
| 2 | 3 | 6692.5 | 103 | 6484.6 | 98 |
| 4 | 1 | 0.5 | 0 | 3020.7 | 0 |

排队时长取调度进程首次入队到首次准入的单调时间差。四轮 64 条测量请求全部完成。上限为 2 时，每轮 C 首次被跳过时 A/B 都在运行，之后还有十条 A/B 请求先于 C 获得准入。D 在上限放宽后仍排队约 3.02 秒，事件记录显示它入队时已有八条请求处于已准入、尚未完成状态，与 `max_num_seqs=8` 一致。这轮容量对照用于归因，正式策略对比仍固定 `max_loras=2`。

第一轮 C 的事件链使用同一请求 ID `cmpl-g1-l2r1-004-C-0-9357d5bf`，时间相对它的首次入队。

| 相对时间 ms | 调度事件 |
|---:|---|
| 0.00 | C 入队 |
| 0.61 | 活跃 LoRA 为 A/B，种类数达到 2，C 首次被跳过 |
| 38.68 | B 的一条新请求准入 |
| 6780.45 | C 首次准入 |
| 7874.10 | C 达到生成上限后完成 |

G2 的首个确定性和真实服务用例固定等待触发阈值为 500 ms。该值低于本轨迹的冷门阻塞时长，便于观察排空全过程。正式评估仍以冷门排队 P95 为主指标，沿用计划书的 B2 对 B1 目标：P95 至少下降 20%，整体 Goodput 降幅不超过 5%。本轮每个冷门适配器样本很少，正式评估的 SLO、采样范围和种子在 G3 开始前锁定。

原始事件、客户端 JSONL、预热记录与摘要位于 `results/g1/fixed-96/`。复跑命令为 `bash scripts/run_g1.sh results/g1/replay-001`。
