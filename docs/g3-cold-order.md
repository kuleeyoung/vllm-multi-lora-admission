# 冷门请求到达顺序诊断

突发补充实验显示 C 大幅获益而 D 等待变化较小。本次诊断区分适配器身份与队列位置，检查先到的冷门请求是否更容易成为排空目标。

复用补充实验 seed 2063 的 48 个计划请求，交换 C 和 D 的模型名。校验表明所有请求的计划偏移、提示词、生成 token 上限和 A/B 模型都与原轨迹一致。C 原先位于约 236 ms 的位置，D 位于约 327 ms 的位置，镜像后身份对调。保留原版 B1/B2 阈值与服务配置。两个适配器使用不同权重，结果用于判断机制是否随到达位置转移，单个种子不足以估计一般负载的收益。

原补充实验 B2 的九波中，三个排空目标均按 C → A → D 的顺序出现。C 首次交接完成时，活跃种类通常成为 B/C。此时原来还在等待的 A 变成了未活跃候选，且其中有请求早于 D 入队，因此会先得到下一轮排空机会。策略按等待时间挑选符合条件的请求，候选既包括在负载定义中标记为冷门的请求，也包括暂时未活跃的热门适配器请求。

原轨迹 seed 2063 的第一波，B2 的 C 在发包窗口开始后约 3.38 秒准入。第 8 号 A 在 3.43 秒触发下一次排空并在 4.66 秒准入。D 到 4.71 秒才成为下一次排空目标，在 6.53 秒准入。B2 给单个请求一次优先检查的范围解释了乍看不一致的结果：C 能立即利用第一份空位，D 仍要经历后续的适配器切换。

## 结果

镜像轨迹的 B1/B2 各完成 48 条请求。两轮均无超时、未准入或抢占；每波完成后到下一波发包前至少有约 0.51 秒空档。

| 轨迹 | B2 排空目标顺序 | 靠前冷门请求成功交接 | 靠后冷门请求成功交接 | 靠前冷门排队 B2−B1 中位差 |
|---|---|---:|---:|---:|
| 原轨迹，三个种子九波 | C → A → D，9/9 波 | 9/9 | 0/9 | −3.41 s |
| 镜像轨迹，seed 2063 三波 | D → A → C，3/3 波 | 3/3 | 0/3 | −5.02 s |

镜像中，B1 的三次错失全部从 C 转为 D，B2 三次都把机会交给了对应的 D。D 的排队 P95 从 9.82 秒降到 4.64 秒，靠后 C 的排队 P95 从 9.83 秒降到 8.93 秒。B1/B2 均有 24 条请求达到既定 SLO，Goodput 持平。镜像的合并冷门 P95 从 9.95 秒降到 8.75 秒，降幅 12.0%，单次诊断未达到 20% 的计划门槛。

收益随靠前的到达位置从 C 转移到 D，两种轨迹均出现先交接给靠前冷门、再处理较早入队的 A、最后处理靠后冷门的顺序。该结果支持按队列位置解释这组轨迹中的收益分布。若要改进两种冷门适配器的合并 P95，下一项策略实验可考察怎样在一次交接完成后同时约束另一个冷门请求和热门请求的继续等待。

原始结果位于 `results/g3/cold-order-ablation-01/`，逐波对照见 `cold-order-waves.csv`。
